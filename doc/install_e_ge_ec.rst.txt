===========================================
Install the Emacs launcher shortcut scripts
===========================================

.. ---------------------------------------------------------------------------

Use this method to quickly install the e_, ge_ and ec_ scripts described in
`Using the Emacs daemon and clients`_
into your Unix compliant system.


- Open a sh-compliant shell (Bash or zsh for example).
- Create ``~/bin`` if it does not exist.
- Ensure GNU Make is available.
- To build the C implementation of ``lses``, provide a C99-capable compiler.
- Put ``emacsclient`` from Emacs 26.1 or later in your ``PATH``.

  - The compiled ``lses`` program requires ``emacsclient`` at runtime.

- Change to the root of your PEL directory.
- Execute one of the following equivalent commands that use the
  `pel/bin/setup/install-emacs-launcher-scripts.sh`_ script that validates
  your environment and creates symbolic links inside your ``~/bin`` directory
  to the PEL executable scripts.  You can use either:

  - Make driven command:   ``make install-launchers``
  - or invoke the script directly: ``bin/setup/install-emacs-launcher-scripts.sh``

- The Make command invokes the shell script.

  - The script creates links in ``~/bin`` to the e_, ge_, ec_,
    ``is-emacs-daemon-running`` and ``is-pel-in-fast-startup`` scripts
    in ``pel/bin``.
  - It builds `lses`_ from ``pel/c/lses/lses.c`` and creates a link
    from ``~/bin/lses`` to ``pel/c/lses/lses``.
    If the build fails, the script asks whether to use the less-powerful
    `pel/bin/lses`_ shell script instead.
    If you accept, the script validates and selects the shell script.
    Replacing an existing ``~/bin/lses`` still requires confirmation.
    If you decline, the installer exits with status 2 and leaves
    ``~/bin/lses`` unchanged.
    Launcher entries processed before the build remain in place.
  - If a destination already exists, the script asks whether to keep
    or replace it.
  - Keep the PEL directory at its installed location. The links depend on it.
  - Add ``~/bin`` to your ``PATH`` if it is not already present.
