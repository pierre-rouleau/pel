Short Commands to start Emacs from the terminal shell
=====================================================

Start single Emacs processes or Emacs daemon and its clients with the
following simple commands POSIX compliant shell commands on Linux and macOS:

- `e`_    : `start Emacs in terminal mode`_,
- `ge`_   : `start Emacs in graphics mode`_,
- `ec`_   : `start Emacs daemons and their clients`_.

Use the following command to get more information about
the running Emacs daemons:

- `ps-emacs`_ : `list currently executing Emacs processes`_.
- `lses`_ : `list name and sockets of all running Emacs daemons`_.

Use ``ec -l`` to list Emacs clients and opened frames.

The installer normally builds and installs the `C implementation of lses`_.
If the build fails, it offers the less-powerful `lses shell implementation`_.

PEL also provides an Emacs launcher installer script that installs these
commands in your environment.  See the `quick installation script`_ page for
more information.

**Caution: When Using Multiple Emacs Programs**

When using different version of Emacs for the text/TTY and graphics mode both
instances of Emacs must use the **same major version**, otherwise the byte
compiled files will only be compatible with the version used to
byte-compile the Emacs Lisp files.  Using Emacs programs that have different
minor versions is normally OK.

**Test Environment:**

The commands were tested in the following environments:

- macOS Sonoma 14.5, Apple Silicon
- macOS Mojave 10.14.6, i386 architecture
- Linux Ubuntu 16.04, i386 architecture
- Linux Ubuntu 22.04, arm64 architecture


Start Emacs in terminal mode with: e
------------------------------------

The e_ command:

- provides help for itself and Emacs,
- can start Emacs to edit files specified on the command line
- can also instruct Emacs to load an `easysession.el`_ named session
  identified by the command line or from the value of the ``PEL_SESSION``
  environment variable,
- the Emacs process gets access to the environment of the current shell.

**Usage**::

  e -- Terminal-based Emacs launcher. Uses 'emacs -nw'.

   Usage: e -h | --help

    • Print this help information.

   Usage: e -- --help

    • Print Emacs help information.

   Usage: e [OPTION-or-FILENAME]...

    • Execute emacs -nw with the specified OPTION-or-FILENAME.
      This does not auto-load any session.

   Usage: e -s [SESSION-NAME] [--] [OPTION-or-FILENAME]...
          e --session=SESSION_NAME [OPTION-or-FILENAME]...
          PEL_SESSION=SESSION-NAME e -s -- [OPTION-or-FILENAME]...

    • Execute emacs -nw, passing the OPTION-or-FILENAME options to Emacs but
      also forcing the automatic loading of an easysession.  The name of the
      session is either specified on the command line as SESSION-NAME or taken
      from the PEL_SESSION environment variable according to the following
      rules:
       • An explicit session name supplied through -s NAME or --session=NAME
         overrides PEL_SESSION.
       • With bare -s, a nonempty PEL_SESSION supplies the session name.
       • With bare -s and an unset or empty PEL_SESSION, the session name
         is set to "."; this requires a directory-specific session whose
         name is extracted by Emacs pel-session logic from the PEL easysession
         catalog file.
       • PEL_SESSION alone does not activate session loading.
         Use -s or --session=NAME to activate session loading.
       • -s does not consume a following argument that starts with a dash.
         Use --session=NAME for such a name.
       • Use -s -- before forwarded arguments when omitting the session name.

    The -s and --session options force the automatic loading of a session
    using the Emacs easysession logic and are active when the following
    conditions are met:
      • The PEL pel-use-easysession      user-option is turned on.
      • The PEL pel-easysession-autoload user-option is turned on.
      • The easysession.el package is installed (PEL installs it when
        Emacs starts and pel-use-easysession is on)
      • The session directory exists (see FILES).

    For a named session, the session file must exist in the easysession
    directory.  When the resolved session name is "." (as is the case for -s
    or with --session=. ) the PEL easysession catalog file (see FILES) must also
    exist and the directory-specific session for it must exist in the easysession
    directory.  The extraction is done by the following steps:
      • e checks that the PEL easysession catalog file exists.  If it exists
        it forces PEL_SESSION value to "." when Emacs starts.
      • When the pel-use-easysession and pel-easysession-autoload user-options
        are turned it proceeds with the following:
        • Emacs pel-session.el checks the value of PEL_SESSION.  If it is "."
          it extracts the session name from the catalog file, otherwise it uses
          that session name.
        • Emacs easysession.el loads the identified named session if it exists.

   FILES
     • Emacs user directory: most often: '~/.emacs.d' but also '~/.config/emacs/'
                             on some XDG compliant systems.
     • session directory: the 'easysession' sub-directory of the Emacs user
                          directory.
     • PEL easysession catalog file:  'pel-easysession-catalog.txt' inside the
                                       Emacs user directory.

   ENVIRONMENT
      • PEL_SESSION_CATALOG : the file name of the PEL easysession catalog file.
                              No path; the file is located inside the user's
                              Emacs directory. Overrides the default shown
                              above.  Required when the user changed the default
                              value of PEL pel-easysession-catalog-filename
                              user-option in Emacs.

   NOTES
      • With the -s option with no named session, place a -- before a following
        file name otherwise it is interpreted as a session name.
      • e starts Emacs within the current shell; Emacs gets access to the
        complete environment of the current shell. This includes the PATH,
        LIBPATH, MANPATH, and several other useful environment variables.  This
        can be useful in many situations.  You can even launch different Emacs
        processes from different shells, each one having different specialized
        environments, and potentially an associated session.

   LIMITATIONS
      • The -s option does not check if a session for the current working
        directory exists in the PEL easysession catalog file.  That is done
        by Emacs pel-session.el logic.  No harm is done: Emacs won't auto-load
        a session.  Use it as a reminder to save the session with a name
        associated with the current working directory.
      • The -s option looks for the default PEL easysession catalog file name:
        the default value of the pel-easysession-catalog-filename user-option.
        If pel-easysession-catalog-filename is modified you must store its
        name in the PEL_SESSION_CATALOG environment variable.
      • When auto-loading a session with easysession via the -s or --session
        option, e assumes that the Emacs user directory currently used is the
        same that was used when session information was saved.  The Emacs user
        directory stores Emacs customization files, package files, easysession
        files, PEL easysession catalog file.  If you invoked Emacs with its
        --init-directory in the past please ensure that you do not need session
        information from that other Emacs user directory as e session
        pre-condition check and execution and Emacs pel-session code both use
        this information to validate and successfully restore an easysession
        session.

   DIAGNOSTICS
    e prints error information on failures. It prints extra details when the
    PEL_DIAG environment variable is set to 1.  Specifically it displays more
    information when conditions are not met for the loading of a session.
    Use that to troubleshoot environment problems.
    • With USRHOME installed, type: setenv PEL_DIAG 1

   EXIT CODE
    • Before launching Emacs:
      • 0 : success,
      • 1 : emacs not found in PATH,
      • 2 : fail to identify emacs users' directory for session load operation,
      • 3 : failed session conditions check; print more info with PEL_DIAG=1,
      • 4 : emacs invoked inside emacs, prompt read failed,
      • 5 : user cancelled recursive Emacs launch attempt
    • After successful exec of Emacs, e returns Emacs's exit status.

   SEE ALSO
    • ge : to start a Graphics-based Emacs process.
    • ec : to start an Emacs daemon server or client.
    • USRHOME : shell environment control with several commands.
                At https://github.com/pierre-rouleau/usrhome
    • For the concept of session auto-loading, see:
      • PEL session PDF : describes how PEL uses easysession.el
      • easysession.el Emacs package documentation.


Start a stand-alone graphics-mode Emacs with: ge
------------------------------------------------

The ge_ command:

- provides help for itself,
- can launch a graphics-mode Emacs process to edit files specified on the command line,
- can also instruct Emacs to load an `easysession.el`_ named session
  identified by the command line or from the value of the ``PEL_SESSION``
  environment variable.
- the Emacs process gets access to the environment of the current shell.

**The PEL_GE_DIR environment variable for macOS and locally built Emacs**

Note that on macOS, if you use a locally built Emacs executable file that has
not been activated as the system Emacs, and you want to use that Emacs
executable in graphics mode with the ge_ and ec_ commands, you will also need
to set the ``PEL_GE_DIR`` environment variable to the name of the directory
holding that Emacs executable file.


**Usage**::

  ge : Launch an independent graphical-mode instance of Emacs.
       Direct launches run in the background with stdout and stderr discarded.
       macOS application launches use open and preserve open's diagnostics.
       Give focus to the graphical Emacs OS window.

   Usage: ge -h | --help

    • Print this help information.

   Usage: ge [OPTION-or-FILENAME]...

    • Launch the graphical Emacs process with the specified OPTION-or-FILENAME.
      The process is launched from within the current directory and inherits the
      current environment variables.
      This does not auto-load any session.

   Usage: ge -s [SESSION-NAME] [--] [OPTION-or-FILENAME]...
          ge --session=SESSION_NAME [OPTION-or-FILENAME]...
          PEL_SESSION=SESSION-NAME ge -s -- [OPTION-or-FILENAME]...

    • Execute a graphical Emacs process, passing the OPTION-or-FILENAME options
      to Emacs but also forcing the automatic loading of an easysession.  The
      name of the session is either specified on the command line as
      SESSION-NAME or taken from the PEL_SESSION environment variable according
      to the following rules:
       • An explicit session name supplied through -s NAME or --session=NAME
         overrides PEL_SESSION.
       • With bare -s, a nonempty PEL_SESSION supplies the session name.
       • With bare -s and an unset or empty PEL_SESSION, the session name
         is set to "."; this requires a directory-specific session whose
         name is extracted by Emacs pel-session logic from the PEL easysession
         catalog file.
       • PEL_SESSION alone does not activate session loading.
         Use -s or --session=NAME to activate session loading.
       • -s does not consume a following argument that starts with a dash.
         Use --session=NAME for such a name.
       • Use -s -- before forwarded arguments when omitting the session name.

    The -s and --session options force the automatic loading of a session
    using the Emacs easysession logic and are active when the following
    conditions are met:
      • The PEL pel-use-easysession      user-option is turned on.
      • The PEL pel-easysession-autoload user-option is turned on.
      • The easysession.el package is installed (PEL installs it when
        Emacs starts and pel-use-easysession is on)
      • The session directory exists (see FILES).

    For a named session, the session file must exist in the easysession
    directory.  When the resolved session name is "." (as is the case for -s
    or with --session=. ) the PEL easysession catalog file (see FILES) must also
    exist and the directory-specific session for it must exist in the easysession
    directory.  The extraction is done by the following steps:
      • ge checks that the PEL easysession catalog file exists.  If it exists
        it forces the PEL_SESSION value to "." when Emacs starts.
      • When the pel-use-easysession and pel-easysession-autoload user-options
        are turned it proceeds with the following:
        • Emacs pel-session.el checks the value of PEL_SESSION.  If it is "."
          it extracts the session name from the catalog file, otherwise it uses
          that session name.
        • Emacs easysession.el loads the identified named session if it exists.

   FILES
     • Emacs user directory: most often: '~/.emacs.d' but also '~/.config/emacs/'
                             on some XDG compliant systems.
     • session directory: the 'easysession' sub-directory of the Emacs user
                          directory.
     • PEL easysession catalog file:  'pel-easysession-catalog.txt' inside the
                                       Emacs user directory.

   ENVIRONMENT
      • PEL_SESSION_CATALOG :
           The file name of the PEL easysession catalog file.  No path; the file
           is located inside the user's Emacs directory. Overrides the default
           shown above.  Required when the user changed the default value of PEL
           pel-easysession-catalog-filename user-option in Emacs.
      • PEL_GE_DIR:
           On macOS only.  Identifies the directory where the emacs graphics-capable
           executable may be stored.  Used if non empty and if executable emacs
           file exists.

   NOTES
      • With the -s option with no named session, place a -- before a following
        file name otherwise it is interpreted as a session name.
      • ge launches Emacs inside an independent OS window, but that process
        inherits the current directory and the complete environment of the
        current shell.  This includes the PATH, LIBPATH, MANPATH, and several
        other useful environment variables.  This can be useful in many
        situations.  You can even launch different Emacs processes from
        different shells, each one having different specialized environments,
        and potentially an associated session.
      • Control is returned right away to the terminal shell.
      • If PEL dual-customization mode is enabled, enable pel-use-easysession
        and pel-easysession-autoload in the graphical-mode customization.
      • For direct graphical Emacs launches, stdout and stderr are discarded.
        Startup errors and external-debugging-output are therefore not visible.
        A successful ge exit status does not confirm successful Emacs startup.

   LIMITATIONS
      • The -s option does not check if a session for the current working
        directory exists in the PEL easysession catalog file.  That is done
        by Emacs pel-session.el logic.  No harm is done: Emacs won't auto-load
        a session.  Use it as a reminder to save the session with a name
        associated with the current working directory.
      • The -s option looks for the default PEL easysession catalog file name:
        the default value of the pel-easysession-catalog-filename user-option.
        If pel-easysession-catalog-filename is modified you must store its
        name in the PEL_SESSION_CATALOG environment variable.
      • When auto-loading a session with easysession via the -s or --session
        option, ge assumes that the Emacs user directory currently used is the
        same that was used when session information was saved.  The Emacs user
        directory stores Emacs customization files, package files, easysession
        files, PEL easysession catalog file.  If you invoked Emacs with its
        --init-directory in the past please ensure that you do not need session
        information from that other Emacs user directory as ge session
        pre-condition check and execution and Emacs pel-session code both use
        this information to validate and successfully restore an easysession
        session.
      • ge will exit in error if the environment does not support launching
        a graphical Emacs, even if the command line does not attempt to open
        a frame or visit files (like to print Emacs help or evaluate elisp code).

   DIAGNOSTICS
    ge prints error information on failures. It prints extra details when the
    PEL_DIAG environment variable is set to 1.  Specifically it displays more
    information when conditions are not met for the loading of a session.
    Use that to troubleshoot environment problems.
    • With USRHOME installed, type: setenv PEL_DIAG 1

   EXIT CODE
    Before launch, ge returns the listed wrapper status codes.
     • For direct background launches, status 0 does not confirm that Emacs
       started successfully. ge does not return Emacs's eventual exit status.
     • For macOS application launches through open, the caller receives open's
       exit status. That status is not Emacs's eventual exit status.
    The exit codes are:
      • 0 : ge processing success.
      • 1 : selected executable or application is missing, or OS is not supported,
      • 2 : fail to identify emacs users' directory for session load operation,
      • 3 : failed session conditions check; print more info with PEL_DIAG=1,
      • 6 : internal logic error that should never happen; please report.

   SEE ALSO
    • e  : to start a terminal-based Emacs process.
    • ec : to start an Emacs daemon server or client.
    • USRHOME : shell environment control with several commands.
                At https://github.com/pierre-rouleau/usrhome
    • For the concept of session auto-loading, see:
      • PEL session PDF : describes how PEL uses easysession.el
      • easysession.el Emacs package documentation.

  OS NOTES
      • On macOS the graphics version of Emacs is taken from a location
        identified by the following logic:
      • If PEL_GE_DIR is nonempty and $PEL_GE_DIR/emacs is executable, use
        that executable. PEL_GE_DIR identifies its containing directory.
        Otherwise, use the executable inside /Applications/Emacs.app
        appropriate for the CPU architecture.

Start Emacs daemons and their clients with: ec
----------------------------------------------

The ec_ command:

- provides help for itself,
- can start the Emacs daemon server,
- can start Emacs daemon clients,
- can check if the Emacs daemon server is running,
- can launch multiple Emacs daemon server when using
  the ``--name`` option:

  - For example, use ``ec --name=PEL`` to start and connect
    to a Emacs daemon that uses the socket named ``PEL``.

    - With this option it is possible to create several
      independent *groups* of Emacs daemon/clients.

- supports daemon and clients in terminal mode and graphics mode.

**Usage**::

  ec : Open specified files in emacsclient. Start Emacs daemon if necessary.

   USAGES:
    ➨ ec [-h|--help]

          -h, --help: print this help.

    ➨ ec [-g|--gui] [--name=DAEMON-NAME] [FILE... | -- CLIENT-ARG...]

          Probe the requested server. If the probe fails, attempt to start
          the daemon. Then open a client connected to the requested socket
          identified by DAEMON-NAME which defaults to 'server'.

          -g, --gui:  start a graphical emacsclient, otherwise
                      start a terminal-based emacsclient (the default).

          Options before the first -- separator belong to ec.
          ec consumes that separator and passes the remaining CLIENT-ARG
          arguments to emacsclient.
          Use the separator for all native client options.
          Plain filenames can be specified before or without the separator.

    ➨ ec -d|--start-daemon [--name=DAEMON-NAME]

          Use --start-daemon to only start the daemon without starting
          any client.
          If the requested server responds, print a message and exit 1.
          Otherwise attempt to start the daemon.
          Client options and filenames are not accepted in this mode.

    ➨ ec -t|--check-daemon [--name=DAEMON-NAME]

          Check whether the requested server responds.
          Use socket server when no name is specified.
          Print the probe result on stdout. The exit code is:
          - 0 if the probe succeeds,
          - 1 for command-line, dependency, or setup errors,
          - 2 if the probe fails.
          Errors are printed on stderr.
          Client options and filenames are not accepted in this mode.

    ➨ ec -l|--list [--name=DAEMON-NAME]

          Show frame and connection counts from the queried Emacs server.
          Then list processes whose command lines contain "emacsclient".

          These counts and the process list measure different things.
          They do not have a one-to-one relationship:

          - A frame can remain after its emacsclient process exits, for
            example when the client uses --no-wait.
          - An emacsclient process can wait for file editing to finish
            without creating a new frame.
          - A server connection is not necessarily a terminal frame.
          - The process list can include clients for other Emacs servers
            or users, subject to process visibility and permissions.
          - Command-line matching can include unrelated processes whose
            arguments contain "emacsclient".
          - Frames, connections, and processes can change between queries.

          A discrepancy can therefore occur during normal operation.
          Hung or orphaned clients are also possible, but a discrepancy
          alone does not establish either condition.
          Matching counts do not establish that all clients work correctly.

          When PEL is available, the command prints more information about
          the client processes and frames.

    A responding server can belong to a daemon or an ordinary Emacs
    session that enabled server-start.
    A failed probe does not prove that no daemon process exists.
    The probe can wait if Emacs is unresponsive.

    The DAEMON-NAME identifies the socket name the Emacs daemon and the
    client must use.  It's possible to create several daemons and client(s)
    attaching to that daemon by using that option.

   EXAMPLES:
       ec -d                         # ec daemon-start mode
       ec -- -d :0 file.txt          # Native client display option
       ec -t                         # ec check mode
       ec -- -t file.txt             # Native client terminal option
       ec --name=work -- --no-wait -d :0 file.txt
       ec --name=work -- --eval '(emacs-version)'
       ec -- -- --help

      The last example opens a file named --help. The second separator
      belongs to emacsclient and ends its option parsing.

      Use --name=NAME before the separator to select the socket.
      Native socket-name, server-file, and alternate-editor options are
      not accepted. Environment variables cannot override that selection.

   SUPPORTED NATIVE CLIENT OPTIONS:
      -H, --help;
        Prints emacsclient help without probing or starting a daemon.
        Do not combine this request with filenames or Lisp expressions to evaluate.

      -V, --version;
        Prints emacsclient version without probing or starting a daemon.
        Do not combine this request with filenames or Lisp expressions to evaluate.

      -e, --eval;
        Evaluate Emacs Lisp expressions on the requested server.
        If the server probe fails, ec attempts to start a daemon.
        If daemon startup fails, ec reports an error and does not send
        the expressions.
        - For evaluation requests, ec does not add terminal (-nw),
          create-frame (-c), or no-wait (-n) options, even when -g is
          specified. Supported native client options that you explicitly
          specify are still passed to emacsclient.
        - All operands are interpreted as Emacs Lisp expressions, not filenames.
          Example:
              ec -- --eval '(emacs-version)'

      -n, --no-wait; -q, --quiet; -u, --suppress-output;
      -t, -nw, --tty, --nw; -c, --create-frame;
      -F, --frame-parameters; -d, --display;
      -p, --parent-id; -T, --tramp.
       The last four options require a value.
       Short options take a separate value. Long options also accept =VALUE.
       Short-option bundles and abbreviated long options are not accepted.
       See the emacsclient manual for option meanings.

   NOTES:
       - Daemon names accepted by this script must not start with a dash
         character.
       - ec can start a graphics-capable server even when it cannot start
         a graphics capable client.  That can occur when executing the command
         from a SSH connected shell for instance.

   OS NOTE:
    On macOS:
       - Under macOS, install /Applications/Emacs.app from
         https://emacsformacosx.com/ or select a local GUI-capable build.
       - You can also use a locally built Emacs, built with GUI support,
         as described in the document How to build Emacs from source in
         the PEL website on Github, at:
         https://github.com/pierre-rouleau/pel/blob/master/doc/build-emacs-from-source.rst.txt
       - You can use the PEL_GE_DIR to identify the directory containing
         specific emacs and emacsclient programs you want to use here.
         The directory must hold the 2 executable programs (or links to them),
         otherwise the default is used.  The default is the macOS Emacs
         application /Applications/Emacs.app.

List currently executing Emacs processes with: ps-emacs
-------------------------------------------------------

The ps-emacs script displays information about the currently running Emacs
processes in lines like the following::

  501 77926 79969   0 Thu08am ttys000    5:14.22 emacs -nw pel--options.el      CWD:  /Users/borg/my/dvp/elisp/pel
  501 70092 54752   0 Thu07am ttys018    0:18.25 emacs -nw .                    CWD:  /Users/borg/my/dvp/testing-dbml

**Usage**::

   ps-emacs -- Print information about all Emacs processes.
              List Emacs processes running in terminal windows first,
              identify the terminal as nicely as possible for those.
              Then list other Emacs processes (such as GUI Emacs).

   Usage: ps-emacs -h | --help

    • Print this help information.

   Usage: ps-emacs [PATTERN]

    • Print information about all running Emacs processes.

        Print a line for each Emacs process.
        Each line contains the following columns.
        All columns are lined up except the last one since
        the command may be short or long.

           UID  : user ID
           PID  : process ID
           PPID : parent process ID
           C    : CPU utilization of process or thread
           STIME: process start time.
           TTY  : controlling terminal
           TIME : total CPU time (user + system) since it started
           CMD  : emacs command
           CWD:  Current working directory of the Emacs process

        The CWD information is only printed when the GNU AWK is available.

      - If PATTERN is specified, filter the result with an extra grep filter
        using that pattern.  That can be used to search for an Emacs process
        launched under a specific command, or using a specific working directory.
      - Under macOS it is best to use gawk (GNU awk) which supports a script that
        deals with terminal number reformatting and allows printing the terminal
        (TTY) numbers nicely on the output.
      - Exit code:
        - 0: one or more Emacs process found (matching PATTERN if one specified).
        - 1: no Emacs process found (and matching PATTERN if one specified).


List name and sockets of all running Emacs daemon with: lses
------------------------------------------------------------

The C implementation of `lses`_ checks discovered sockets and reports responsive
Emacs daemons, including their names, socket paths and process IDs.
It also identifies responsive non-daemon servers and reports socket problems.
It requires ``emacsclient`` from Emacs 26.1 or later in ``PATH``.

The usage and exit statuses below describe the C implementation.

The shell fallback only lists discovered socket entries.
It supports Linux and macOS.

It does not explicitly reject other operating systems, but support
for those systems is not provided.

It does not confirm that an Emacs daemon responds or report process IDs.
It does not support ``--verbose``.
For the shell fallback's usage, run ``lses --help`` if the fallback is installed,
or run ``bin/lses --help`` from the PEL root directory.

**Usage**::

  lses -- List current Emacs daemon servers & sockets.

  Usage: lses -h | --help

   • Print this help information.

  Usage: lses [-v | --verbose]

   • Report responsive Emacs daemons with their names, sockets and PIDs.
     Also report responsive non-daemon servers and socket problems.
     With --verbose, also print a summary when no responsive daemon
     is confirmed.

  Requires emacsclient from Emacs 26.1 or later in PATH.
  Searches EMACS_SOCKET_NAME, XDG_RUNTIME_DIR/emacs,
  TMPDIR/emacsUID (default /tmp).
  On macOS it also searches the macOS temporary fallback.
  Searches immediate directory entries only.

  Connection deadline: 1 second per socket.
  Emacs response deadline: 3 seconds per socket.
  Never starts Emacs or deletes discovered sockets.

  Exit status:
    0: at least one responsive Emacs daemon confirmed.
    1: local program error or client execution failure.
    2: no responsive Emacs daemon confirmed.

  LIMITATION: lses only supports Linux and macOS.

Using Emacs daemon on macOS
===========================

**Goal**:  Provide ability to launch a graphical (GUI) or text-based (TTY)
Emacs client from a macOS terminal.

**Challenge**: Several people, including myself, had problems launching the
graphical based Emacs client from the terminal, regardless of the
``emacsclient`` command line used.  All instances of Emacs client programs
ended up being terminal based only.

**Solution**: The key is to use an Emacs binary that supports Emacs in graphics
mode to launch the Emacs daemon.  Once this done, it becomes possible to
launch graphical Emacs clients and text-based Emacs clients:

- To launch a graphical based Emacs client use a *graphics-capable*
  ``emacsclient`` binary.
- To launch a text based Emacs client, you can use two methods:

  - Use a *graphics-capable* Emacs and issue the command ``emacsclient -nw``
  - Use a text-based Emacs and issue one of the following 2 commands:

    - ``emacsclient -c`` or
    - ``emacsclient -nw``

On macOS, the *graphics-capable* Emacs is one of the Emacs binary files inside
the ``/Applications/Emacs.app`` universal DMG directory tree from `Emacs for
Mac OS X`_ installed manually or from the Homebrew ``brew install --cask
emacs`` command.


**Other Considerations**

Under macOS (as of macOS Sonoma in 2024), if you want to launch an independent
terminal-based Emacs process from the terminal shell, it is best to use an
Emacs binary that was built *without* graphical capabilities because it starts
faster than an Emacs that was built with graphical capabilities.

Because of that you may want to install *two* instances of Emacs on macOS:

- one with graphical capabilities and
- one that does not have them built-in.

Fortunately it's possible to do both without having to build Emacs locally:
Homebrew supports installing both as long as you follow some steps to trick
it.

Installing Emacs on macOS
=========================

First install the graphics-capable version of Emacs for macOS. This can be
done in two different ways:

- Download and install Emacs from `Emacs for Mac OS X`_, or
- Use the `Homebrew package manager`_ and issue the following command from your
  terminal::

    brew install --cask emacs

Both install the same macOS universal DMG from `Emacs for Mac OS X`_.

At this point, Homebrew won't let you install another version of emacs.
You need to trick it.

- First **copy** the Emacs DMG ( ``/Applications/Emacs.app`` ) somewhere else.
- Next, uninstall Homebrew's installed (cask) Emacs with:  ``brew uninstall --cask emacs``.
- Then install the terminal-only version of Emacs with Homebrew by issuing the
  following command: ``brew install emacs``
- Finally, put your ``Emacs.app`` copy back into ``/Applications`` so you will
  now also have ``/Applications/Emacs.app``

At this point, if you type ``which emacs`` you should see that it is installed
inside a Homebrew controlled directory.  For macOS running on Apple Silicon
processors, that's ``/opt/homebrew/bin/emacs``.

Launching Independent Emacs Processes
=====================================

The next sections list the explicit commands to launch Emacs in a specific
way.  These assume Emacs was installed in macOS as described in the previous
section.

Launching an independent terminal Emacs process from a terminal shell
---------------------------------------------------------------------

Explicit command line::

  emacs

or::

  emacs -nw

or use the `e`_ command `described above`_.

Launching an independent graphical Emacs process from a terminal shell
----------------------------------------------------------------------

Explicit command line::

  open -n -a /Applications/Emacs.app/Contents/MacOS/Emacs

This uses the macOS open command with the following command line options:

- ``-n``: open a new instance on each invocation
- ``-a application``: identify the path of the application

You can also use the `ge`_ command `described above`_.

Launching an independent graphical Emacs process from macOS Finder
------------------------------------------------------------------

Assuming no Emacs daemon is running, you can use Spotlight to open Emacs from
the keyboard:

- Type ``⌘-SPACE`` then Emacs and ``RET``

Note that when you use this, Emacs runs under the default OS environment.
In some case that may mean that you wont have access to programs you may want to use because
they are not present in any directory listed in the systems' PATH.

There are several solutions to this problem.

#. Use PEL's ability to configure the environment variables from customization: customize
   PEL's **pel-gui-process-environment** user-option.

   - Type ``C-h o pel-gui-process-environment RET`` from Emacs and access the customization
     buffer. Then insert new environment variables with their value or identify strings to append or
     prepend to existing environment variables (like ``PATH``).  You can create or update any
     number of environment variables.  The docstring of this customizable user-option
     provides more information.

#. Use the `exec-path-from-shell`_ package.  It launches a shell to extract the environment
   from it when Emacs starts.

The first method, provided by PEL, is very flexible but it requires setting it
through the powerful Emacs customization system.  It also has very negligible impact on Emacs
startup time.  The second method requires installation of another package and assumes that you
only have one shell configured the way you want.


Launching a *graphics-capable* Emacs Daemon
===========================================

Explicit command line for an Emacs daemon with the default socket name::

   /Applications/Emacs.app/Contents/MacOS/Emacs --daemon

If you want to create multiple Emacs daemon, each one must identify a socket
by name.  The command is::

   /Applications/Emacs.app/Contents/MacOS/Emacs --daemon --socket-name=FILENAME


where, according the emacsclient man page:

  Use socket named FILENAME for communication.  Relative filenames
  are relative to "$XDG_RUNTIME_DIR/emacs/" or "$TMPDIR/".

  See also the EMACS_SOCKET_NAME environment variable, over which
  this option takes precedence.


Opening Emacs Clients to the running Emacs Daemon
=================================================


Opening a graphics-based Emacs client
-------------------------------------

Explicit command for macOS running on Apple Silicon::

  /Applications/Emacs.app/Contents/MacOS/bin-arm64-11/emacsclient -c -n

Opening a text-based Emacs client
---------------------------------

Explicit command using the mac OS X Emacs, for macOS on Apple Silicon::

  /Applications/Emacs.app/Contents/MacOS/bin-arm64-11/emacsclient   -nw


Explicit command using the text-based Emacs installed with Homebrew ``brew
install emacs`` command::

   emacsclient -nw
