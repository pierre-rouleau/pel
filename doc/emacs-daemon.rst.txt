Short Commands to start Emacs from the terminal shell
=====================================================

Start single Emacs processes or Emacs daemon and its clients with the
following simple commands:

- e_  : `start Emacs in terminal mode`_
- ge_ : `start Emacs in graphics mode`_
- ec_ : `start Emacs daemons and their clients`_

The commands are POSIX shell scripts and explicitly support Linux and macOS.


Start Emacs in terminal mode with: e
------------------------------------

The e_ command:

- provides help for itself and Emacs,
- can start Emacs to edit files specified on the command line
- can also instruct Emacs to load an `easysession.el`_ named session
  identified by the command line or from the value of the ``PEL_SESSION``
  environment variable,
- the Emacs process gets access to the environment of the current shell.

**Usage**::

  e -- Terminal-based Emacs launcher. Uses 'emacs -nw'.

   Usage: e -h | --help

    • Print this help information.

   Usage: e -- --help

    • Print Emacs help information.

   Usage: e [OPTION-or-FILENAME]...

    • Execute emacs -nw with the specified OPTION-or-FILENAME.
      This does not auto-load any session.

   Usage: e -s [SESSION-NAME] [--] [OPTION-or-FILENAME]...
          e --session=SESSION_NAME [OPTION-or-FILENAME]...
          PEL_SESSION=SESSION-NAME e -s [OPTION-or-FILENAME]...

    • Execute emacs -nw, passing the OPTION-or-FILENAME
      options to Emacs but also forcing the automatic
      loading of an easysession.  The name of the session
      is either specified on the command line as SESSION-NAME
      or taken from the PEL_SESSION environment variable according
      to the following rules:
       • An explicit session name supplied through -s NAME or --session=NAME
         overrides PEL_SESSION.
       • With bare -s, a nonempty PEL_SESSION supplies the session name.
       • With bare -s and an unset or empty PEL_SESSION, the session name
         is set to "."; this requires a directory-specific session whose
         name is extracted by Emacs pel-session logic from the PEL easysession
         catalog file.
       • PEL_SESSION alone does not activate session loading; the -s option
         is required.
       • -s does not consume a following argument that starts with a dash.
         Use --session=NAME for such a name.
       • Use -s -- before forwarded arguments when omitting the session name.

    The -s and --session options force the automatic loading of a session
    using the Emacs easysession logic and are active when the following
    conditions are met:
      • The PEL pel-use-easysession      user-option is turned on.
      • The PEL pel-easysession-autoload user-option is turned on.
      • The easysession.el package is installed (PEL installs it when
        Emacs starts and pel-use-easysession is on)
      • The session directory exists (see FILES).
    For unnamed, directory-specific session invoked with -s without a name,
    the following extra condition must be met for the loading of the
    session.  e checks the first, Emacs pel-session code checks the other two:
      • The PEL easysession catalog file exists (see FILES).
      • It has a line that identifies a session for the current directory.
      • That file is present in the session directory.

   FILES
     • Emacs user directory: most often: '~/.emacs.d' but also '~/.config/emacs/'
                             on some XDG compliant systems.
     • session directory: the 'easysession' sub-directory of the Emacs user
                          directory.
     • PEL easysession catalog file:  'pel-easysession-catalog.txt' inside the
                                       Emacs user directory.

   ENVIRONMENT
      • PEL_SESSION_CATALOG : the file name of the PEL easysession catalog file.
                              No path; the file is located inside the user's
                              Emacs directory. Overrides the default shown
                              above.  Required when the user changed the default
                              value of PEL pel-easysession-catalog-filename
                              user-option in Emacs.

   NOTES
      • e starts Emacs within the current shell; Emacs gets access to the
        complete environment of the current shell. This includes the PATH,
        LIBPATH, MANPATH, and several other useful environment variables.  This
        can be useful in many situations.  You can even launch different Emacs
        processes from different shells, each ones having different specialized
        environments, and potentially an associated session.

   LIMITATIONS
      • The -s option does not check if a session for the current working
        directory exists in the PEL easysession catalog file.  That is done
        by Emacs pel-session.el logic.  No harm is done: Emacs won't auto-load
        a session.  Use it as a reminder to save the session with a name
        associated with the current working directory.
      • The -s option looks for the default PEL easysession catalog file name:
        the default value of the pel-easysession-catalog-filename user-option.
        If pel-easysession-catalog-filename is modified you must store its
        name in the PEL_SESSION_CATALOG environment variable.
      • When auto-loading a session with easysession, e assumes that the
        session information was stored inside files located inside the same
        Emacs user directory Emacs will use now.  It does not support
        restoration of sessions created by invoking Emacs with its
        --init-directory option.

   DIAGNOSTICS
    e print error information on failures. It prints extra details when the
    PEL_DIAG environment variable is set to 1.  Specifically it displays more
    information when conditions are not met for the loading of a session.
    Use that to troubleshoot environment problems.
    • With USRHOME installed, type: setenv PEL_DIAG 1

   EXIT CODE
    • Before launching Emacs:
      • 0 : success,
      • 1 : command line error,
      • 2 : emacs not found in PATH,
      • 3 : emacs invoked inside emacs, prompt read failed,
      • 4 : fail to identify emacs users' directory for session load operation.
    • After successful exec of Emacs, the command returns Emacs's exit status.

   SEE ALSO
    • ge : to start a Graphics-based Emacs process.
    • ec : to start a Emacs daemon server or client.
    • USRHOME : shell environment control with several commands.
                At https://github.com/pierre-rouleau/usrhome
    • For the concept of session auto-loading, see:
      • PEL session PDF : describes how PEL uses easysession.el
      • easysession.el Emacs package documentation.

Start a stand-alone graphics-mode Emacs with: ge
------------------------------------------------

The ge_ command:

- provides help for itself,
- can launch a graphics-mode Emacs process to edit files specified on the command line,
- can also instruct Emacs to load an `easysession.el`_ named session
  identified by the command line or from the value of the ``PEL_SESSION``
  environment variable.
- the Emacs process gets access to the environment of the current shell.

**The PEL_GE_DIR environment variable for macOS and locally built Emacs**

Note that on macOS, if you use a locally built Emacs executable file that has
not been activated as the system Emacs, and you want to use that Emacs
executable in graphics mode with the ge_ and ec_ commands, you will also need
to set the ``PEL_GE_DIR`` environment variable to the name of the directory
holding that Emacs executable file.


**Usage**::

  ge : Open an independent, detached, graphical-mode instance of Emacs.

   Usage: ge -h | --help

    • Print this help information.

   Usage: ge [OPTION-or-FILENAME]...

    • Launch the graphical Emacs process with the specified Emacs
      OPTION-or-FILENAME.
      The process is launched from within the current directory and inherits the
      current environment variables.
      This does not auto-load any session.

   Usage: ge [-s] [SESSION-NAME] [--] [OPTION-or-FILENAME]...
          ge --session-name=SESSION_NAME [OPTION-or-FILENAME]...
          PEL_SESSION=SESSION-NAME ge -s [OPTION-or-FILENAME]...

    • Execute the graphical Emacs process, passing it the OPTION-or-FILENAME
      options.
      The process is launched from within the current directory and inherits the
      current environment variables.  This also forces the automatic loading of
      an easysession.
      The name of the session is either specified on the command line as
      SESSION-NAME or taken from the PEL_SESSION environment variable according
      to the following rules:
      • If -s is specified without any session name after the -s
        or with the PEL_SESSION=SESSION-NAME before the script name
        and PEL_SESSION environment variable does not already exist
        or is currently empty, then the script requires the use of the
        directory-specific session.
        • This is the session name associated with the current directory
          identified inside the PEL easysession catalog file:
          ~/.emacs.d/pel-easysession-catalog.txt
        • If you need to specify '-s' without a session name and need to pass
          other arguments to Emacs use '-s --'.
      • If '-s' is specified with no session name but the PEL_SESSION
        environment variable has a non-empty value, the session with that name
        is auto-loaded.  The, special name '.' (without quotes) identifies a
        directory-specific session name extracted from the PEL easysession
        catalog.
      • Any word (except '--') directly following '-s', '--session-name=' or the
        'PEL_SESSION=' identifies the session name and overrides the
        session name that could be identified by the current value of
        the PEL_SESSION environment variable.

    The -s and --session-name options force the automatic loading of a session
    using the Emacs easysession logic and are active when the following
    conditions are met:
      • The PEL pel-use-easysession user-option is turned on in the graphics mode
        customization.
      • The PEL pel-easysession-autoload user-option is turned on in the graphics
        mode customization.
      • The easysession.el package is installed (PEL installs it when
        Emacs starts and pel-use-easysession is on)
      • The ~/.emacs.d/easysession directory exists.
      • The ~/.emacs.d/pel-easysession-catalog.txt file exists.
        • It has a line that identifies a session for the current directory.
        • That file is present in the ~/.emacs.d/easysession directory.

  NOTES
      • ge launches Emacs inside an independent OS window, but that process
        inherits the current directory and the complete environment of the
        current shell.  This includes the PATH, LIBPATH, MANPATH, and several
        other useful environment variables.  This can be useful in many
        situations.  You can even launch different Emacs processes from
        different shells, each ones having different specialized environments,
        and potentially an associated session.
      • Control is returned right away to the terminal shell.
      • Remember that PEL supports the dual-customization mode where
        customization of Emacs in terminal mode is independent that the
        customization of Emacs in graphics mode.

   DIAGNOSTICS
    The script is silent by default.  To force it to display error messages to
    describe unmet conditions for the -s option, set the PEL_DIAG environment
    variable to 1.  If there is a problem, it will be displayed and the script
    will exit before invoking Emacs.  Use that to troubleshoot environment
    problems.
    • With USRHOME installed, type: setenv PEL_DIAG 1

   SEE ALSO
    • e  : to start a terminal-based Emacs process.
    • ec : to start a Emacs daemon server or client.
    • USRHOME : shell environment control with several commands.
                At https://github.com/pierre-rouleau/usrhome

  OS NOTES
      • On macOS the graphics version of Emacs is taken from one of the
        following locations, checked in the following order:
        • If PEL_GE_DIR environment variable is defined, it must identify
          the path of an emacs executable file that launches in graphics
          mode by default.  If the environment variable is set and
          $PEL_GE_DIR/emacs is valid then that is used.
          Currently this is: ~/my/bin/emacs
          Use this, for example, if you have built Emacs yourself
          and want to use this version of Emacs without activating it
          by default in your shells or in the system.
        • If /Applications/Emacs.app/Contents/MacOS exists and holds
          an appropriate Emacs executable file, that is used.

   BUGS: On macOS Sonoma, the started Emacs application window is
         buried under the window of the current terminal shell.
         This problem does not occur on macOS Mojave.

Start Emacs daemons and their clients with: ec
----------------------------------------------

The ec_ command:

- provides help for itself,
- can start the Emacs daemon server,
- can start Emacs daemon clients,
- can check if the Emacs daemon server is running,
- can launch multiple Emacs daemon server when using
  the ``--name`` option:

  For example, use ``ec --name=PEL`` to start and connect
  to a Emacs daemon that uses the socket named ``PEL``.

  - With this option it is possible to create several
    independent *groups* of Emacs daemon/clients.

- supports daemon and clients in terminal mode and graphics mode.

**Usage**::

  ec : Open specified files in emacsclient. Start Emacs daemon if necessary.

   USAGES:
    ➨ ec [-h|--help]

          -h, --help: print this help.

    ➨ ec [-g|--gui] [--name=DAEMON-NAME] [OPTION-or-FILENAME]...

          If the Emacs daemon is not already running, start it.
          -g, --gui:  start a graphical emacsclient, otherwise
                      start a terminal-based emacsclient (the default).

    ➨ ec --start-daemon [--name=DAEMON-NAME] [OPTION-or-FILENAME]...

          Use --start-daemon to only start the daemon without starting
          any client.
          If the daemon is already running the command prints a message
          and exit with an exit code of 1.  You can use it to check if the
          daemon is running.

    ➨ ec --check-daemon [--name=DAEMON-NAME] [OPTION-or-FILENAME]...

          The --check-daemon is used to explicitly check if the Emacs
          daemon for the default socket is running.

        For the last 2 commands, if the --name option is specified,
        DAEMON-NAME identifies the socket name the daemon and the client
        must use.  It's possible to create several daemons and client(s)
        attaching to that daemon by using that option.

        The OPTION-or-FILENAME is the set of emacsclient options and the
        name of the files to edit.  All emacsclient options are supported
        when specified last.
        See emacsclient man page for information about those.

   Note: Under macOS, to be able to launch an Emacs client that is a GUI
         Emacs the GUI supporting Emacs such as Emacs from
         https://emacsformacosx.com/ must be installed.

         You can also use a locally built Emacs, built with GUI support,
         as described in the document How to build Emacs from source in
         the PEL website on Github, at:
         https://github.com/pierre-rouleau/pel/blob/master/doc/build-emacs-from-source.rst.txt

   Note: Under Linux, emacs-lucid is used to start the daemon if the --gui
         option is specified and the emacs-lucid executable file is found
         on the current PATH.  Otherwise, ec defaults to emacs.

     ENVIRONMENT:
         To use the locally built Emacs in graphics mode you will also need
         to set the PEL_GE_DIR environment variable to the name of the
         directory holding the Emacs executable file.

Using Emacs daemon on macOS
===========================

**Goal**:  Provide ability to launch a graphical (GUI) or text-based (TTY)
Emacs client from a macOS terminal.

**Challenge**: Several people, including myself, had problems launching the
graphical based Emacs client from the terminal, regardless of the
``emacsclient`` command line used.  All instances of Emacs client programs
ended up being terminal based only.

**Solution**: The key is to use an Emacs binary that supports Emacs in graphics
mode to launch the Emacs daemon.  Once this done, it becomes possible to
launch graphical Emacs clients and text-based Emacs clients:

- To launch a graphical based Emacs client use a *graphics-capable*
  ``emacsclient`` binary.
- To launch a text based Emacs client, you can use two methods:

  - Use a *graphics-capable* Emacs and issue the command ``emacsclient -nw``
  - Use a text-based Emacs and issue one of the following 2 commands:

    - ``emacsclient -c`` or
    - ``emacsclient -nw``

On macOS, the *graphics-capable* Emacs is one of the Emacs binary files inside
the ``/Applications/Emacs.app`` universal DMG directory tree from `Emacs for
Mac OS X`_ installed manually or from the Homebrew ``brew install --cask
emacs`` command.


**Other Considerations**

Under macOS (as of macOS Sonoma in 2024), if you want to launch an independent
terminal-based Emacs process from the terminal shell, it is best to use an
Emacs binary that was built *without* graphical capabilities because it starts
faster than an Emacs that was built with graphical capabilities.

Because of that you may want to install *two* instances of Emacs on macOS:

- one with graphical capabilities and
- one that does not have them built-in.

Fortunately it's possible to do both without having to build Emacs locally:
Homebrew supports installing both as long as you follow some steps to trick
it.

Installing Emacs on macOS
=========================

First install the graphics-capable version of Emacs for macOS. This can be
done in two different ways:

- Download and install the Emacs the `Emacs for Mac OS X`_, or
- Use the `Homebrew package manager`_ and issue the following command from your
  terminal::

    brew install --cask emacs

Both install the same macOS universal DMG from `Emacs for Mac OS X`_.

At this point, Homebrew won't let you install another version of emacs.
You need to trick it.

- First **copy** the Emacs DMG ( ``/Applications/Emacs.app`` ) somewhere else.
- Next, uninstall Homebrew's installed (cask) Emacs with:  ``brew uninstall --cask emacs``.
- Then install the terminal-only version of Emacs with Homebrew by issuing the
  following command: ``brew install emacs``
- Finally, put your ``Emacs.app`` copy back into ``/Applications`` so you will
  now also have ``/Applications/Emacs.app``

At this point, if you type ``which emacs`` you should see that it is installed
inside a Homebrew controlled directory.  For macOS running on Apple Silicon
processors, that's ``/opt/homebrew/bin/emacs``.

Launching Independent Emacs Processes
=====================================

The next sections list the explicit commands to launch Emacs in a specific
way.  These assume Emacs was installed in macOS as described in the previous
section.

Launching an independent terminal Emacs process from a terminal shell
---------------------------------------------------------------------

Explicit command line::

  emacs

or::

  emacs -nw

or use the `e`_ command `described above`_.

Launching an independent graphical Emacs process from a terminal shell
----------------------------------------------------------------------

Explicit command line::

  open -n -a /Applications/Emacs.app/Contents/MacOS/Emacs

This uses the macOS open command with the following command line options:

- ``-n``: open a new instance on each invocation
- ``-a application``: identify the path of the application

You can also use the `ge`_ command `described above`_.

Launching an independent graphical Emacs process from macOS Finder
------------------------------------------------------------------

Assuming no Emacs daemon is running, you can use Spotlight to open Emacs from
the keyboard:

- Type ``⌘-SPACE`` then Emacs and ``RET``

Note that when you use this, Emacs runs under the default OS environment.
In some case that may mean that you wont have access to programs you may want to use because
they are not present in any directory listed in the systems' PATH.

There are several solutions to this problem.

#. Use PEL's ability to configure the environment variables from customization: customize
   PEL's **pel-gui-process-environment** user-option.

   - Type ``C-h o pel-gui-process-environment RET`` from Emacs and access the customization
     buffer. Then insert new environment variables with their value or identify strings to append or
     prepend to existing environment variables (like ``PATH``).  You can create or update any
     number of environment variables.  The docstring of this customizable user-option
     provides more information.

#. Use the `exec-path-from-shell`_ package.  It launches a shell to extract the environment
   from it when Emacs starts.

The first method, provided by PEL, is very flexible but it requires setting it
through the powerful Emacs customization system.  It also has very negligible impact on Emacs
startup time.  The second method requires installation of another package and assumes that you
only have one shell configured the way you want.


Launching a *graphics-capable* Emacs Daemon
===========================================

Explicit command line for an Emacs daemon with the default socket name::

   /Applications/Emacs.app/Contents/MacOS/Emacs --daemon

If you want to create multiple Emacs daemon, each one must identify a socket
by name.  The command is::

   /Applications/Emacs.app/Contents/MacOS/Emacs --daemon --socket-name=FILENAME


where, according the emacsclient man page:

  Use socket named FILENAME for communication.  Relative filenames
  are relative to "$XDG_RUNTIME_DIR/emacs/" or "$TMPDIR/".

  See also the EMACS_SOCKET_NAME environment variable, over which
  this option takes precedence.


Opening Emacs Clients to the running Emacs Daemon
=================================================


Opening a graphics-based Emacs client
-------------------------------------

Explicit command for macOS running on Apple Silicon::

  /Applications/Emacs.app/Contents/MacOS/bin-arm64-11/emacsclient -c -n

Opening a text-based Emacs client
---------------------------------

Explicit command using the mac OS X Emacs, for macOS on Apple Silicon::

  /Applications/Emacs.app/Contents/MacOS/bin-arm64-11/emacsclient   -nw


Explicit command using the text-based Emacs installed with Homebrew ``brew
install emacs`` command::

   emacsclient -nw
