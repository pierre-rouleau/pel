Overview
========

PEL's fast startup mode reduces Emacs startup time by re-organizing the ELPA
packages on disk and by generating small bits of startup code so that Emacs
does far less work at startup:

- It creates a flat, one-level “bundle” directory of symlinks to all ``.el``/
  ``.elc`` files from one-level ELPA packages — drastically shrinking the
  number of directories in ``load-path``.
- For Emacs ≥ 27, it optionally integrates with ``package-quickstart`` so that
  Emacs reads one precomputed file instead of scanning all installed packages.
- It optionally applies early-init optimizations (GC threshold boost,
  ``file-name-handler-alist`` suppression, disable UI elements early) so Emacs
  performs less work while loading.

Fast startup is toggled with:

- ``M-x pel-setup-fast`` — generate the bundle and fast startup init file,
  switch symlinks, and prepare optional quickstart.
- ``M-x pel-setup-normal`` — restore normal operation and (if enabled) rebuild
  quickstart for the full package set.

Changes take effect on the next Emacs start.

General Principles
==================

Standard startup costs with many packages
------------------------------------------

1. Package directory scanning to build ``package-alist``.
2. Package activation and reading per-package metadata files.
3. ``require`` search across hundreds of ``load-path`` entries.
4. Frequent GC during heavy loading.
5. Work done by file name handlers (TRAMP, compression) for each ``load``.
6. UI frames created, then torn down, then redrawn.

How fast startup reduces those costs
-------------------------------------

- One flat directory for one-level packages minimizes directory probes and
  speeds up ``require`` lookups (early in ``load-path``).
- ``package-quickstart`` (Emacs ≥ 27) removes the per-directory scan entirely.
- Early-init optimizations:
  - GC boost during init, restored after startup.
  - Temporarily suppress ``file-name-handler-alist``.
  - Disable menu/tool/scroll bars before first frame in graphics mode.

Runtime Directory Structure (user-emacs-directory)
==================================================

.. list-table:: Fast-startup related directories and files
   :header-rows: 1
   :widths: 35 65

   * - Path
     - Role
   * - ``elpa-complete/``
     - The canonical ELPA store for terminal/TTY mode.
   * - ``elpa-complete-graphics/``
     - Canonical ELPA store for graphics mode when dual environment is enabled.
   * - ``elpa/`` (symlink)
     - Points to ``elpa-complete/`` in normal mode, to ``elpa-reduced/`` in fast mode.
   * - ``elpa-graphics/`` (symlink)
     - Graphics-mode counterpart when dual environment is enabled.
   * - ``elpa-reduced/`` (directory)
     - Fast-startup directory. Contains a time-stamped “pel-bundle-YYYYMMDD.hhmm”.
   * - ``elpa-reduced-graphics/``
     - Graphics-mode counterpart in dual environment.
   * - ``elpa-attic/``
     - Retired/renamed packages moved here by PEL cleanup.
   * - ``pel-bundle/pel-bundle-YYYYMMDD.hhmm/``
     - The generated “bundle” (a flat directory of symlinks to one-level package files) plus:
       - ``pel-bundle-autoloads.el`` (generated autoloads)
       - ``pel-bundle-pkg.el`` (package descriptor for the pseudo-package)
   * - ``pel-fast-startup-init.el``
     - Generated file containing ``pel-fast-startup-init``. Loaded by early-init/init.
   * - ``package-quickstart.el`` (and ``-graphics`` variant)
     - Generated by Emacs when quickstart is enabled.

-----------------------------------------------------------------------------

Files Involved
==============

User files in ``~/.emacs.d/``
-----------------------------

- ``early-init.el`` (Emacs ≥ 27): detects graphics vs terminal for dual env,
  optionally enables quickstart and early-init optimizations, and triggers fast
  startup by loading ``pel-fast-startup-init`` if present.
- ``init.el``: main initialization; in fast startup it defers
  ``pel--init-package-support`` to ``emacs-startup-hook``; otherwise initializes
  packages early as usual.
- ``pel-fast-startup-init.el``: generated by ``pel-setup-fast``; sets up the
  bundle in ``load-path``, records the original ``package-user-dir`` early, and
  adds built-in version info for bundled dependencies so package.el does not
  try to download them.
- ``package-quickstart.el`` and optional ``package-quickstart-graphics.el``:
  created via ``package-quickstart-refresh``.

Key PEL source files
--------------------

- ``pel-setup.el``: top-level orchestrator; implements
  ``pel-setup-fast``/``pel-setup-normal``; generates ``pel-fast-startup-init.el``;
  manages symlinks and bundle creation.
- ``pel-setup-base.el``: shared utilities (init file updates, symlink checks,
  mode reporting, quickstart prompts).
- ``pel-setup-27.el``: Emacs ≥ 27 helpers (early-init updates, quickstart
  generation/removal).
- ``pel-elpa.el``: bundle mechanics:

  - ``pel-elpa-create-copies`` — builds the flat symlink bundle from one-level packages,
    excluding ``*-pkg.el`` and ``elpa.el``/``elpa.elc`` developer artifacts.
  - ``pel-elpa-remove-pure-subdirs`` — removes one-level package directories from
    ``elpa-reduced`` because their files live in the bundle.
  - ``pel-elpa-disable-pkg-deps-in`` — collects dependency versions to seed
    ``package--builtin-versions``.

- ``pel-package.el``: ELPA directory helpers, attic moves, stats, and cleanup:

  - ``pel-elpa-dirpath``, ``pel-elpa-attic-dirpath`` and related path helpers.
  - ``pel-cleanup`` — top-level cleanup, including renamed-package handling.
  - ``pel--elpa-package-renames`` and ``pel-clean-renamed-packages`` — retire
    superseded packages (e.g., ``go-translate`` → ``gt``) to ``elpa-attic`` to
    avoid filename collisions in the bundle.

- ``pel--base.el``: environment helpers; ``pel-in-fast-startup-p``.
- ``pel--options.el``: customization variables controlling fast startup,
  quickstart, dual environment, and early-init optimizations.

How pel-setup-fast Works
========================

When you execute ``M-x pel-setup-fast`` (and confirm):

1. Validate init/early-init files and preconditions.
2. Ensure ``elpa`` (and possibly ``elpa-graphics``) is a symlink to an
   ``elpa-complete`` directory; fix if needed.
3. Remove the previous ``elpa-reduced`` tree (keeps bundles time-stamped in parent).
4. Create a temporary ``pel-bundle`` directory (sibling of ``elpa``).
5. Copy/symlink all ``.el``/``.elc`` from one-level packages in
   ``elpa-complete`` into ``pel-bundle`` (via ``pel-elpa-create-copies``).
   - Excludes: ``*-pkg.el`` and ``elpa.el``/``elpa.elc``.
   - Duplicate basenames: warns and keeps the first encountered path.
6. Generate ``pel-bundle-autoloads.el`` and ``pel-bundle-pkg.el`` in the bundle.
7. Duplicate ``elpa-complete`` to ``elpa-reduced`` and remove one-level
   package subdirectories (their files live in the bundle).
8. Disable dependencies for remaining multi-directory packages in
   ``elpa-reduced`` and collect dependency version info to seed
   ``package--builtin-versions`` at startup.
9. Move the finished ``pel-bundle`` under ``elpa-reduced`` with a timestamped
   name (e.g., ``pel-bundle-20260519.1420``).
10. Generate ``pel-fast-startup-init.el``:

    - Records the original ``package-user-dir`` in
      ``pel-package-user-dir-original`` (prevents a spurious graphics-mode
      compliance warning).
    - Adds bundle dependency versions to ``package--builtin-versions``.
    - For Emacs ≥ 27 with quickstart, ensures the bundle directory is added
      to ``load-path`` during early-init.
    - Advises ``package-load-all-descriptors`` to select graphics/TTY variant
      appropriately when dual environment is enabled.

11. For Emacs ≥ 27 if quickstart is enabled, rebuild
    ``package-quickstart.el`` for the active elpa directory.
12. Point the ``elpa`` (and optionally ``elpa-graphics``) symlink(s) at
    ``elpa-reduced``.

Dual environment
----------------

When ``pel-init-support-dual-environment-p`` is enabled, steps 2–12 are run
for the terminal set (plain) and for the graphics set (``-graphics``), maintaining
independent custom files, elpa directories and optional quickstart files.

-----------------------------------------------------------------------------

How pel-setup-normal Works
==========================

``M-x pel-setup-normal`` reverses the setup:

1. Switches symlink(s) back to ``elpa-complete``.
2. Removes the fast-startup marker file (``pel-fast-startup-init.el``).
3. For Emacs ≥ 27, updates early-init settings and (if quickstart is enabled)
   rebuilds ``package-quickstart.el`` for the full package set.
4. Leaves ``elpa-reduced`` on disk so a later ``pel-setup-fast`` can reuse it.

-----------------------------------------------------------------------------

Bundle Details (pel-elpa-create-copies)
=======================================

- Operates on the source ELPA root (``elpa-complete`` or its graphics variant).
- Copies or symlinks only ``.el`` and ``.elc`` files from one-level packages.
- Excludes:

  - ``*-pkg.el`` and ``*-pkg.elc`` (installation metadata only).
  - Basenames in ``pel--bundle-excluded-basenames`` (currently ``"elpa"``)
    which are developer artifacts, not runtime code.

- Duplicate basenames:

  - Emits a warning and keeps the first path encountered.
  - Typical false positives (e.g., ``elpa.el`` in multiple repos) are excluded.
  - Genuine collisions (e.g., rename pairs like ``go-translate`` vs ``gt``)
    should be resolved by retiring the old package (see below).

Handling renamed ELPA packages
------------------------------

- PEL keeps an extensible mapping in ``pel--elpa-package-renames``
  (e.g., ``(go-translate . gt)``).
- ``pel-clean-renamed-packages``:

  - If both old and new package directories exist in the active elpa,
    moves the old one to ``elpa-attic``.
  - Removes the old package from ``package-selected-packages`` (in memory and
    in the custom file), preventing future attempts to activate it.

- ``pel-cleanup`` calls ``pel-clean-renamed-packages`` first, then proceeds
  with general unused-package cleanup.

Emacs Version Notes
===================

- Emacs ≤ 26:

  - ``package-initialize`` ran automatically and activated all installed
    packages; quickstart does not exist.
  - Fast startup uses the bundle only.

- Emacs ≥ 27:

  - ``package-quickstart`` is available; when enabled, Emacs reads
    ``package-quickstart.el`` during early-init and does not scan directories.
  - ``pel-setup-27.el`` updates early-init and (re)builds quickstart files.

- Emacs ≥ 29:

  - Quickstart remains the preferred acceleration path; PEL’s bundle continues
    to reduce directory traversal and ``require`` probing.

-----------------------------------------------------------------------------

Early-init Optimizations (optional)
===================================

Controlled by customization variables in ``pel--options.el`` and written into
``early-init.el`` by PEL commands:

- ``pel-early-init-support-gc-boost-p``:
  Raise ``gc-cons-threshold``/``gc-cons-percentage`` during startup and restore
  them after ``emacs-startup-hook``.
- ``pel-early-init-suppress-file-name-handler-p``:
  Temporarily set ``file-name-handler-alist`` to ``nil`` during startup.
- ``pel-early-init-disable-ui-elements-p`` (graphics only):
  Disable toolbar/menu bar/scroll bars via ``default-frame-alist`` in
  early-init; prevents draw-then-teardown.

-----------------------------------------------------------------------------

Batch statistics (make stats) and activation
============================================

The Makefile target::

  emacs --batch -L . -l $(EMACS_INIT) -l pel-package.el -f pel-package-info-all

On Emacs ≥ 27, early activation can occur before the custom file sets
``package-selected-packages``. ``pel-package-info-all`` now explicitly calls
``package-activate-all`` (or ``package-initialize`` on Emacs 26) after PEL has
loaded and after the custom file is in effect, so ``package-activated-list`` is
complete and consistent for reporting.

Troubleshooting
===============

Graphics-mode “init.el does not comply” warning in fast startup
----------------------------------------------------------------

Cause: ``pel-package-user-dir-original`` was not set yet when
``pel-package.el`` was loaded early in graphics mode. Fix: the generated
``pel-fast-startup-init`` (written by ``pel-setup-fast``) now records the
original ``package-user-dir`` immediately upon entry, preventing the warning.

Rename collisions (e.g., go-translate → gt)
--------------------------------------------

If both old and new packages are installed, the bundle will detect duplicate
basenames (``gt-*.el``). Run ``M-x pel-cleanup``; it will move the old package
to ``elpa-attic`` and scrub it from ``package-selected-packages``.

Harmless duplicate artifacts (``elpa.el``)
-------------------------------------------

Some packages carry a legacy ``elpa.el`` used only for development. These are
automatically excluded from the bundle and do not require action.

-----------------------------------------------------------------------------

Typical Workflow
================

- Normal → Fast:
  1. Optionally run ``M-x pel-cleanup`` (cleans unused and renamed packages).
  2. Run ``M-x pel-setup-fast``.
  3. Restart Emacs.

- Fast → Normal:
  1. Run ``M-x pel-setup-normal``.
  2. Restart Emacs.

- After adding/removing packages in normal mode:
  1. Return to normal if needed (``pel-setup-normal``).
  2. Install/remove packages.
  3. Rebuild fast startup (``pel-setup-fast``) and restart.

Customization Variables (selection)
===================================

- User-option defined in ``pel--options.el`` that you can set via customization:

  - ``pel-support-package-quickstart`` (Emacs ≥ 27): enable/disable
    quickstart.
  - ``pel-compile-emacs-init``: controls compilation of ``init.el`` after PEL
    updates it.  Three values are supported:

    - ``nil`` (do not compile; deletes any existing ``.elc``),
    - ``t`` (byte-compile only), or
    - ``byte-and-native-compile-it`` (byte-compile and native-compile;
      default).

  - ``pel-compile-emacs-early-init``: same three-value choice as above for
    ``early-init.el`` (where the file is early-init instead of init).

- Constant defined inside ``~/.emacs.d/init.el``.
  Edit that file to modify its value:

  - ``pel-init-support-dual-environment-p``: separate terminal vs graphics
    custom files and package directories.

- Constants defined inside the ``~/.emacs.d/early-init.el``
  Edit that file to modify their values:

  - ``pel-early-init-support-gc-boost-p``: GC threshold boost during init.
  - ``pel-early-init-suppress-file-name-handler-p``: suppress file handlers.
  - ``pel-early-init-disable-ui-elements-p``: disable UI elements early.

Activate them all to get the fastest Emacs startup.
