Objectives
==========

- Track the time for the tasks of multiple projects.
- Create a report of active and completed tasks and the time spent for them.
- The report must include:

  - time spent today,
  - time spent daily this week,
  - time spent weekly, for the last 3 weeks,
  - time spent monthly, for the last 3 months.

- The report must track time of tasks underway and the completed tasks.
- The tasks can be organized as a hierarchy of parent tasks, with sub-tasks
  and sub-sub-tasks.

  - Five level should be allowed.
  - The hierarchy should be visible in the generated report.

- The system must support tracking of activities related to several,
  independent, activities or projects.  For instance it should be possible to
  track consulting work for different customers independently.
- Information from completed tasks should be  removed from the file describing
  the active tasks and placed into an archive.

  - This reduces the clutter in the active task file.

- All data must be stored under a VCS to provide protection against loss and
  allow correction of errors.

Methodology Used
================

The idea is to use Emacs Org Mode and store project-specific information
inside a project-specific Org file into a directory tree that is under VCS
control.

First we create a directory tree to hold all Org files.
In this example, we're tracking the activities of 3 projects, P1, P2 and P3.
We create the following directory tree and their files under the directory
``~/my``::


      my/project-tracking
      ├── master.org
      ├── project1
      │   ├── p1.org
      │   └── p1.org_archive
      ├── project2
      │   ├── p2.org
      │   └── p2.org_archive
      └── project3
          ├── p3.org
          └── p3.org_archive


The file my/project-tracking/master.org is setup to hold the report of all
activities.  Each project has its own directory with a main file (like p1.org)
and an archive file (like p1.org_archive).

The directory ``my/project-tracking`` is the VCS root.  Use the VCS or DVCS of your
choice and add all these files to it.  I personally use either Git or
Mercurial for this but you can use anything.


Setting Up the Files
--------------------

The Master File
~~~~~~~~~~~~~~~

Store the content of PEL `example/templates/org-mode/master-org.org`_ file inside
your master.org file.

The Main Project File
~~~~~~~~~~~~~~~~~~~~~

For each project should have its own directory.  The name of the directory can
be anything relevant, the name of the file should be short, but provide enough
information as it will appear in the report.

You could split major activities in several files for each project or keep
them inside one file per project for simplicity.

Each of these file must be an ``.org`` file and should contain something like
the following from PEL `example/templates/org-mode/project.org`_ ::

    -*- mode: org; org-duration-format: h:mm; -*-

    #+STARTUP: content
    #+COLUMNS: %25ITEM %4TODO %3PRIORITY %TAGS

This instructs Org to track the number of hours and minutes, and never print time in
number of days.

The Org Archive Files
~~~~~~~~~~~~~~~~~~~~~

Each project main ``.org`` file will also have a corresponding Org archive
file, either created by Org when archiving a task or by copying the content
of PEL `example/templates/org-mode/project.org_archive`_ ::

      #    -*- mode: org -*-

      #+STARTUP: content

Note that the first line might not be written when the file is created by
archiving a tasks.  It's best to add it so you can view the Org archive file
with org-mode.


Setup the Project
-----------------

Once the file hierarchy is created, Org must be aware of them.

Notice the ``:scope pel-org-get-project-files`` at the end of the
``clocktable`` line inside the master.org file.  This is the name of a PEL
function that returns the list of relevant files identified by the
``pel-org-project-files`` customizable user option.

Therefore to complete the setup you must customize the following user-options:

= ==================================== ==========================================
. PEL user-option                      Description
= ==================================== ==========================================
. ``pel-use-org``                      Activates PEL support for Org.

                                       - Set it to **t** to activate it.

. ``pel-org-archive-with-hierarchy``   Control whether the task hierarchy is
                                       identified and maintained in the Org
                                       archive files.

                                       - Turn it one (set it to **t**) if you
                                         want to see the task hierarchy in the
                                         report for the archived tasks.

. ``pel-org-project-files``            Identifies the Org and Org archive
                                       files that will be scanned when creating or refreshing
                                       the time reports.

                                       - Identify the path of each of your project and project
                                         archive files.

= ==================================== ==========================================


Generating an Activity Report
-----------------------------

Once you have information stored in your Org project files, have logged
time in them, and setup the require PEL user options (as described in the
previous section), you can create or refresh a time tracking report by saving all
your Org files containing relevant information and opening the master.org
file.

Inside the master.org file, locate the lines that start with ``#+BEGIN:
clocktable`` and type ``C-c C-c`` on them to create or refresh the relevant
report.

There's 4 different reports in the recommended file and the first one is to
track the tasks done on this current day.

Here's how it might look inside a terminal-based Emacs::

    * Todays' Log
    #+BEGIN: clocktable :maxlevel 5 :step day :tstart "<today>" :tend "<now>" :narrow 60  (require 'org-clock) (require 'org-table) :scope pel-org-get-project-files
